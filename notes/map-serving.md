# TensorFold serving-stack code map (top of the stack)

Repo root: `TensorFold/`. All paths below are relative to that root.
Every anchor was read at the line numbers given. Backend-agnostic/reference code is preferred; where an
optimised twin exists it is mapped beside the reference.

**Stack in one line:**
`routes.zig` (method/path) → `openai.zig` (parse + SSE adapter) → `chat.zig:prepare` (template → token ids,
window checks, sampling resolution) → `engine.submit` → `Mailbox` (engine thread → request thread) →
`chat_generation.zig:loop` (per-round token commit, stop checks, incremental detokenise) → `sse.zig` frames.
Inside the engine: `core/lanes/engine.zig:conclude` (sample → accept draft path → append KV) with
`core/lanes/sampling.zig` / `gpu_rule.zig` / `kernels/metal/nemotron/sample.metal` as the three sampler tiers.

## 1. HTTP method/path dispatch

- **Anchor**: `zig/src/server/routes.zig:118-160`
- **What it does**: `post` is the whole POST router. It classifies the path with suffix matches (so `/v1/chat/completions`
  and `/chat/completions` are the same route), refuses unknown paths after draining the body, picks a load-ledger
  route group, passes through the admission gate, then tail-calls `openai.post(srv, conn, a, is_chat)` for both
  `/v1/chat/completions` and `/v1/completions`. The single `is_chat` boolean is the only difference between the
  two OpenAI text routes from here down.
- **Excerpt**:
```zig
fn post(srv: *Server, conn: *Conn, a: Allocator) void {
    const route = auth.routePath(conn.path);
    if (cancel_ids.match(route)) |rid| { // an admin action: answered at once, outside admission
        discardBody(conn, a);
        return cancel_ids.post(srv, conn, a, rid);
    }
    for (tokens.paths) |r| if (std.mem.eql(u8, route, r)) return tokens.post(srv, conn, a, std.mem.endsWith(u8, route, "/detokenize"));
    const is_speech = std.mem.eql(u8, route, "/v1/audio/speech");
    const is_embedding = std.mem.eql(u8, route, "/v1/embeddings");
    const is_chat = std.mem.endsWith(u8, route, "/chat/completions");
    if (!is_ocr and !is_rerank and !is_embedding and !is_speech and !is_images and !is_slide and imprint_op == null and !is_anthropic and !is_responses and !is_decisions and !is_systemone and !is_chat and !std.mem.endsWith(u8, route, "/completions")) {
        discardBody(conn, a);
        return unknown(conn, a);
    }
    const kind: request_gate.RouteKind = .{ .text = is_text, .embedding = is_embedding, .rerank = is_rerank, .systemone = is_systemone };
    var entered = request_gate.enter(srv, a, conn.key_digest, group, kind);
    defer entered.held.release();
    if (entered.refusal) |refusal| return refuse(conn, a, is_anthropic, refusal);
    openai.post(srv, conn, a, is_chat);
}
```
- **Teaching value**: a "route table" can be 40 lines of string comparisons; the OpenAI surface is a thin
  adapter and chat vs. raw-completion is one flag, not two code paths.
- **Gotchas**: a refused route **reads and discards the body** (`discardBody`) so a keep-alive connection can't
  bleed one request's body into the next. `GET` is a separate function (`routes.zig:85-113`), which is where
  `/v1/models` lands. `auth.routePath` normalises trailing slashes and query strings, so `/v1/completions///?x=1`
  is the same route.

## 2. `GET /v1/models`

  `api.Info.Capability` enum, so the wire shape can never drift from the engine's capability set.
- **Excerpt**:

- **Teaching value**: `/v1/models` is the client's capability-discovery handshake, not just a name list — it is

- **Gotchas**: `inline for (@typeInfo(api.Info.Capability).@"enum".field_names)` in `modelValue`

## 3. Request parse: the OpenAI body becomes a `chat.Input`

- **Anchor**: `zig/src/server/openai.zig:129-182`
- **What it does**: `plan()` is the single pre-flight: it parses/validates numbers, resolves
  `max_tokens` vs `max_completion_tokens`, copies the **sampling-relevant field names verbatim** into an opaque
  `input.fields` object (so later layers can ask "did the client name this key?"), reads the thinking switches,
  and returns `{input, stream, separate_usage, policy, named}`. Anything refused here is a 400 **before** any
  stream is opened.
- **Excerpt**:

- **Teaching value**: sampling knobs are carried as a **key-presence-preserving JSON object**, not as a struct of
  defaults. That is what lets "the request named top_k" be distinguished from "top_k happens to be 0".

## 4. SSE emission

- **Anchor**: `zig/src/server/sse.zig:1-42` (whole file)
- **What it does**: The entire Server-Sent-Events wire format: `open` writes the 200 with
  `text/event-stream` + `no-cache` + `Connection: close`; `data` writes one `data: {json}\n\n` frame as a single
  write; `comment` writes `: keepalive\n\n`; `done` writes `data: [DONE]\n\n`; `event` writes the
  `event: KIND` form used by the Responses and Anthropic Messages routes.
- **Excerpt**:
```zig
/// 200 with text/event-stream; the connection closes after the stream.
pub fn open(conn: *Conn) error{Closed}!void {
    conn.startResponse(200, null) catch return error.Closed;
    conn.addHeader("Content-Type", "text/event-stream") catch return error.Closed;
    conn.addHeader("Cache-Control", "no-cache") catch return error.Closed;
    conn.addHeader("Connection", "close") catch return error.Closed;
    return conn.finish("");
}

/// ``data: {json}`` and a blank line, sent at once.
pub fn data(conn: *Conn, _: Allocator, payload: json.Value) error{Closed}!void {
    var frame = std.heap.ArenaAllocator.init(conn.gpa);
    defer frame.deinit();
    const a = frame.allocator();
    const text = json.stringify(a, payload, .{}) catch return error.Closed;
    return conn.writeAll(std.mem.concat(a, u8, &.{ "data: ", text, "\n\n" }) catch return error.Closed);
}

/// An SSE comment line, which clients skip: it keeps a stream alive while nothing else is sent.
pub fn comment(conn: *Conn) error{Closed}!void {
    return conn.writeAll(": keepalive\n\n");
}

pub fn done(conn: *Conn) error{Closed}!void {
    return conn.writeAll("data: [DONE]\n\n");
}
```
- **Teaching value**: "streaming an LLM" is literally 35 lines of text framing. Everything hard is upstream.
- **Gotchas**: the JSON for each frame is built in a **per-frame arena** that is destroyed immediately, so a long
  stream does not grow the request arena. Each frame is one `writeAll` so a frame can never be split by another
  writer. `: keepalive` comment frames exist because a client that times out a silent stream would disconnect
  during a long prefill (see the `beat` branch in the decode loop, §9).

The adapter that binds the generic reply sink to this connection:

- **Anchor**: `zig/src/server/openai.zig:58-89`

`if (p.stream) r.stream(gone, field) else r.whole(gone, field)`, and `Run.stream` begins at
`zig/src/server/openai.zig:505-548`.

## 5. Chat templating: messages → one token sequence

### 5a. The Jinja renderer (reference, backend-independent)

- **Anchor**: `zig/src/core/template/template.zig:212-232`
- **What it does**: `run` is the variable-binding step of TensorFold's own Jinja2-compatible engine. It binds
  exactly HuggingFace's chat-template contract: `messages`, `tools`, `documents`, `add_generation_prompt`, then
  any extra `chat_template_kwargs` from `context` (which may not shadow the three reserved names), then evaluates
  the compiled AST. `compile` (`template.zig:164-178`) lexes/parses/scopes and fails on unknown filters, as
  Jinja2's compiler does.
- **Excerpt**:
```zig
fn run(c: *eval.Ctx, vars: *v.Map, t: *const Compiled, messages: std.json.Value, tools: std.json.Value, context: std.json.Value, template_globals: std.json.Value, add_generation_prompt: bool) v.Error!void {
    const a = c.rt.a;
    if (template_globals == .object) {
        var it = template_globals.object.iterator();
        while (it.next()) |e| try vars.put(a, e.key_ptr.*, try pyjson.fromJsonDerived(&c.rt, e.value_ptr.*, false));
    }
    try vars.put(a, "messages", try pyjson.fromJson(&c.rt, messages));
    try vars.put(a, "tools", try pyjson.fromJson(&c.rt, tools));
    try vars.put(a, "documents", .none);
    try vars.put(a, "add_generation_prompt", .{ .boolean = add_generation_prompt });
    if (context == .object) {
        var it = context.object.iterator();
        while (it.next()) |e| {
            const key = e.key_ptr.*;
            if (std.mem.eql(u8, key, "messages") or std.mem.eql(u8, key, "tools") or std.mem.eql(u8, key, "add_generation_prompt")) continue;
            try vars.put(a, key, try pyjson.fromJson(&c.rt, e.value_ptr.*));
        }
    }
    try eval.root(c, t.tree);
}
```
- **Teaching value**: the chat "format" is not code — it is a Jinja template shipped with the checkpoint, and the
  engine's only job is to bind five variables and run it.
- **Gotchas**: `renderProvenanceGlobals` (`template.zig:192-209`) renders **text plus byte provenance spans**, so
  the tokenizer can later know which output bytes came from untrusted request content (that is what feeds
  `encodeMasked`, §6). The render runs under a `Capped` allocator (`template.zig:194`) that converts a runaway
  template into "needs more than N MiB to render this request" instead of an OOM.

### 5b. The server's prompt pipeline (normalise, render, close a dangling `<think>`)

- **Anchor**: `zig/src/server/prompt.zig:36-78`
- **What it does**: `renderRequest` normalises messages for this template family, renders with
  `enable_thinking`/`reasoning_effort`/`tool_choice`/`response_format` as template options, then performs the
  two thinking-block repairs: for MiniMax-M3 it appends the `</mm:think>` token when thinking is off, and for
  Qwen-style templates it detects that the rendered prompt **ends with a bare `<think>`** and appends `</think>`
  so the model starts in the answer. If thinking-off was explicitly requested and the template offers no switch
  and no closable prefix, it refuses.
- **Excerpt**:
```zig

    const normalized = if (srv.text.vtable.format == .kimi or srv.text.native_deepseek) messages_in else try messages_mod.toolArguments(cx, messages_in);
    var problem: []const u8 = "";
    const options: model_text.RenderOptions = .{
        .tools = if (tools.len > 0) Value{ .array = @constCast(tools) } else null,
        .add_generation_prompt = generation,
        .enable_thinking = thinking,
        .reasoning_effort = if (thinking) effort else cx.named_effort, // off: only an effort the request named
        .clear_thinking = cx.clear_thinking,
        .tool_choice = cx.template_fields.get("tool_choice"),
        .response_format = cx.template_fields.get("response_format"),
        .images = srv.info.vision != null,
    };
    const rendered = render(srv, cx.a, normalized, options, &problem) catch |e| switch (e) {
        error.OutOfMemory => return error.OutOfMemory,
        error.Template => return cx.fail(.request, "{s}", .{problem}),
    };
    var ids = rendered.ids;
    var closed = rendered.closed;
    if (!thinking and generation and ids.len > 0) {
        const last = try srv.text.decode(cx.a, ids[ids.len - 1 ..]);
        if (std.mem.eql(u8, @import("reply_text.zig").pyStrip(last), "<think>")) {
            const close = srv.text.encode(cx.a, "</think>", false) catch |e| switch (e) {
                error.OutOfMemory => return error.OutOfMemory,
                error.Template => &[_]u32{},

            if (close.len == 1) {
                ids = try std.mem.concat(cx.a, u32, &.{ ids, close });
                closed = true;
            }
```

- **Teaching value**: "thinking off" is not a model flag — it is a prompt-suffix trick: the template still opens
  the think block, so the server closes it immediately so the first sampled token is already the answer.
- **Gotchas**: `prompt.zig:145-170` (`prepare`) renders the **same conversation up to three more times** — once
  without the generation prompt to find `history_len`, once with a probe assistant turn (`continuedLen`,
  `prompt.zig:171-187`) and once for `rewindLen` — purely to learn how many leading tokens the prompt cache can
  reuse. `replySpans` (`prompt.zig:128-143`) locates earlier assistant replies inside the prompt by searching for
  the generation-prompt token run and the next EOS.

### 5c. Tool-call and thinking-block parsing on the way back out

- **Anchor**: `zig/src/server/reply_text.zig:121-196`
- **What it does**: `splitThinkingAt` splits a reply into `{reasoning, answer}`. The close can be found three
  ways (`Close` at `reply_text.zig:88-96`): `.spelled` (search the text for `</think>`), `.token` (the close is a
  real token and its byte offset is known — so a `</think>` the model *quotes* in prose stays prose), or
  `.pending` (the close token exists in this tokenizer but has not arrived, so everything so far is reasoning).
  While streaming (`finished == false`) it holds back any trailing bytes that could be the start of a marker.
- **Excerpt**:
```zig
/// Where the reply's reasoning ends, from its tokens: the close token's bytes, the text's spelling, or all of it.
pub fn closeWhere(a: Allocator, decode: anytype, ctx: anytype, tokens: []const u32, close_id: ?u32) !Close {
    const id = close_id orelse return .spelled;
    const at = std.mem.indexOfScalar(u32, tokens, id) orelse return .pending;
    if (at == 0) return .{ .token = 0 };
    const through = try decode(ctx, a, tokens[0 .. at + 1]);
    defer a.free(through);
    const marker = try decode(ctx, a, tokens[at .. at + 1]);
    defer a.free(marker);
    // Include separators the decoder inserts before the selected token, without searching for a quoted spelling.
    return .{ .token = through.len -| marker.len };
}
```
and the streaming hold-back, `reply_text.zig:74-79`:
```zig
/// How many bytes at the end of ``text`` could begin ``tag``.
pub fn partialTag(text: []const u8, tag: []const u8) usize {
    if (tag.len == 0) return 0;
    var k = @min(tag.len - 1, text.len);
    while (k > 0) : (k -= 1) if (std.mem.endsWith(u8, text, tag[0..k])) return k;
    return 0;
}
```
- **Teaching value**: reasoning/tool markup must be split **by token identity, not by string search**, or a model
  that writes the literal characters `</think>` inside prose truncates its own answer.
- **Gotchas**: the tool-call openers are a table of six marker pairs (`reply_text.zig:21-27`: Qwen
  `<tool_call>`, Gemma 4 `<|tool_call>`, three DSML spellings, LFM2 `<|tool_call_start|>`), each with an optional
  "payload lead" (`reply_text.zig:30`) so `payloadOf` (`reply_text.zig:46-53`) can answer *call / wait / prose*.
  `hideInto` (`reply_text.zig:201-247`) caches each opener's next position and only re-searches once `pos` passes
  it — a deliberate avoidance of O(markers × length) rescanning — and returns a **slice of the input** with zero
  copying when the text contains no call block.

## 6. Tokenizer: encode

- **Anchor**: `zig/src/core/tokenizer/tokenizer.zig:183-200`
- **What it does**: `Tokenizer.encode` is byte-for-byte equivalent to HF `tokenizers`'
  `encode(text, add_special_tokens=False)`. It replaces invalid UTF-8 with U+FFFD, splits the text on
  added/special tokens with a byte trie (leftmost-longest, `Trie` at `tokenizer.zig:53-105`), and hands each
  remaining gap to `encodeSegment` → normaliser → pre-tokeniser → the word model.
- **Excerpt**:
```zig
    pub fn encode(t: *const Tokenizer, a: Allocator, text: []const u8) Error![]u32 {
        var stack: [scratch_stack_bytes]u8 = undefined;
        var fallback = std.heap.BufferFirstAllocator.init(&stack, t.allocator);
        var arena = std.heap.ArenaAllocator.init(fallback.allocator());
        defer arena.deinit();
        var ctx = steps.Context{ .a = arena.allocator(), .matcher = .{ .a = arena.allocator() } };
        var valid = text;
        if (!std.unicode.utf8ValidateSlice(text)) {
            var fixed: std.ArrayList(u8) = .empty;
            try unicode.appendLossy(&fixed, ctx.a, text);
            valid = fixed.items;
        }
        var ids: std.ArrayList(u32) = .empty;
        for (try t.splitAdded(&ctx, &t.raw, valid)) |seg| {
            if (seg.id) |id| try ids.append(ctx.a, id) else if (seg.end > seg.start) try t.encodeSegment(&ctx, valid[seg.start..seg.end], seg.start == 0, &ids);
        }
        return a.dupe(u32, ids.items);
    }
```
- **Teaching value**: encoding is a *pipeline*, not one algorithm: added-token split → normalise → pre-tokenise
  (regex split) → per-word model. Special tokens never go through BPE.
- **Gotchas**:
  - `scratch_stack_bytes = 4096` (`tokenizer.zig:21`): small encodes allocate **nothing on the heap** —
    `BufferFirstAllocator` serves from a stack buffer and only spills past 4 KiB.
  - `encodeSegment` (`tokenizer.zig:258-266`) routes long segments through a `Memo` cache so a repeated
    conversation prefix is not re-BPE'd every turn.
  - `encodeMasked` / `encodeMaskedCounted` (`tokenizer.zig:205-249`) is the security path: request-supplied byte
    spans (from the template's provenance, §5a) may not participate in an added-token spelling; a span that would
    produce an added token raises `error.UnsafeAddedTokenMask`. This is how a user who types `<|im_end|>` cannot
    forge a turn boundary.

### 6a. The BPE algorithm itself

- **Anchor**: `zig/src/core/tokenizer/model.zig:67-131`
- **What it does**: Classic pair-merge BPE over a doubly-linked symbol list with a priority queue keyed by
  `(merge rank, position)`. Also implements `ignore_merges` (whole-word shortcut), byte fallback to `<0xNN>`
  tokens, and `fuse_unk`. `WordPiece` (longest-prefix) and `WordLevel` live in the same file
  (`model.zig:133-157` and `model.zig:51`).
- **Excerpt**:
```zig
    fn bpe(m: *const Model, ctx: *steps.Context, vocab: *const Vocab, word: []const u8, out: *std.ArrayList(u32)) Error!void {
        const a = ctx.a;
        if (m.ignore_merges) if (m.id(vocab, word)) |whole| return out.append(a, whole);
        var symbols: std.ArrayList(Symbol) = .empty;
        var pending_unk: ?u32 = null;
        var piece: std.ArrayList(u8) = .empty;
        var i: usize = 0;
        while (i < word.len) {
            const len = unicode.decodeAt(word, i).len;
            var s = word[i .. i + len];
            // ... prefix/suffix decoration, vocab hit, byte_fallback, unk handling ...
        }
        const syms = symbols.items;
        for (syms, 0..) |*s, k| {
            s.prev = @as(i32, @intCast(k)) - 1;
            s.next = if (k + 1 < syms.len) @intCast(k + 1) else -1;
        }
        var queue = std.PriorityQueue(Candidate, void, order).empty;
        for (0..syms.len -| 1) |k| if (m.pair(syms[k].id, syms[k + 1].id)) |hit|
            try queue.push(a, .{ .rank = hit.rank, .pos = @intCast(k), .id = hit.id });
        while (queue.pop()) |top| {
            const s = &syms[top.pos];
            if (!s.alive or s.next < 0) continue;
            const right: usize = @intCast(s.next);
            const current = m.pair(s.id, syms[right].id) orelse continue;
            if (current.id != top.id) continue;
            s.id = top.id;
            s.next = syms[right].next;
            syms[right].alive = false;
            if (s.next >= 0) syms[@intCast(s.next)].prev = @intCast(top.pos);
            if (s.prev >= 0) if (m.pair(syms[@intCast(s.prev)].id, s.id)) |hit|
                try queue.push(a, .{ .rank = hit.rank, .pos = @intCast(s.prev), .id = hit.id });
            if (s.next >= 0) if (m.pair(s.id, syms[@intCast(s.next)].id)) |hit|
                try queue.push(a, .{ .rank = hit.rank, .pos = top.pos, .id = hit.id });
        }
        for (syms) |s| if (s.alive) try out.append(a, s.id);
    }
```
- **Teaching value**: the whole of BPE is "repeatedly merge the lowest-ranked adjacent pair" — the linked list +
  heap is just a way to avoid rescanning.
- **Gotchas**: stale heap entries are tolerated rather than removed (`if (!s.alive ...) continue;` and
  `if (current.id != top.id) continue;`) — a lazy-deletion heap, which is why no decrease-key is needed.
  **BPE dropout is refused at load** (`model.zig:245-252`: `return error.UnsupportedModel`) because a random
  merge policy has no exact encoding. Merge ranks are stored as a single `u64` key `left << 32 | right`
  (`model.zig:63-65`).

### 6b. Vocab loading

```zig
    defer a.free(file);
```

  bytes at load (`model.zig:270-273`). Added tokens are registered in `addTokens`

## 7. Tokenizer: decode, and incremental/streaming detokenisation

### 7a. Batch decode and exact token bytes

- **Anchor**: `zig/src/core/tokenizer/tokenizer.zig:407-437`
- **What it does**: `decode` maps ids to piece strings (skipping unknown ids, and specials when asked) and runs
  the decoder chain. `tokenBytes` returns one token's **exact, possibly incomplete UTF-8 bytes** — it returns
  `null` for decoders whose output depends on neighbours, which is the signal that per-token byte reporting
  (logprobs `bytes` field) is impossible for this tokenizer.
- **Excerpt**:
```zig
    /// Text for `ids` through the decoder chain; unknown ids are skipped. Caller frees with `a`.
    pub fn decode(t: *const Tokenizer, a: Allocator, ids: []const u32, skip_special_tokens: bool) Error![]u8 {
        var stack: [scratch_stack_bytes]u8 = undefined;
        var fallback = std.heap.BufferFirstAllocator.init(&stack, t.allocator);
        var arena = std.heap.ArenaAllocator.init(fallback.allocator());
        defer arena.deinit();
        var ctx = steps.Context{ .a = arena.allocator(), .matcher = .{ .a = arena.allocator() } };
        var tokens = try std.ArrayList([]const u8).initCapacity(ctx.a, ids.len);
        for (ids) |id| {
            const token = t.id_to_token.get(id) orelse continue;
            if (skip_special_tokens and t.specials.contains(token)) continue;
            tokens.appendAssumeCapacity(token);
        }
        if (t.decoder) |*d| return d.decode(a, &ctx, tokens.items);
        return std.mem.join(a, " ", tokens.items);
    }

    /// Exact, possibly incomplete UTF-8 bytes; null for context-dependent decoders. Caller frees with `a`.
    pub fn tokenBytes(t: *const Tokenizer, a: Allocator, id: u32) Error!?[]u8 {
        const d = if (t.decoder) |*decoder| decoder else return null;
        if (!d.tokenLocal()) return null;
        const piece = t.id_to_token.get(id) orelse return try a.dupe(u8, "");
        if (t.specials.contains(piece)) return try a.dupe(u8, piece);
        // ... raw_bytes ctx ...
        return try d.decode(a, &ctx, &.{piece});
    }
```
- **Gotchas**: with no `decoder` in `tokenizer.json`, HF joins pieces with a **space** — faithfully reproduced
  here. `ctx.raw_bytes = true` in `tokenBytes` is what suppresses the lossy U+FFFD substitution so logprob
  `bytes` rows stay lossless.

### 7b. The incremental detokeniser (the tricky part)

- **Anchor**: `zig/src/server/reply_text.zig:452-485`
- **What it does**: `Incremental` decodes **only the new tokens with the previous chunk as context**, so a
  character split across two tokens is emitted whole. It advances the committed prefix only when the re-decode
  both produced more *characters* and does **not** end in U+FFFD; otherwise it holds everything back until the
  continuation token arrives. `pending()` reports that state to the caller.
- **Excerpt**:
```zig
/// Decodes only new tokens with the previous chunk as context, so characters split across tokens stay whole.
pub const Incremental = struct {
    tokens: std.ArrayList(u32) = .empty,
    text: std.ArrayList(u8) = .empty,
    prefix: usize = 0,
    read: usize = 0,
    close: ?Close = null, // where the reasoning ends, once the close token has arrived

    pub fn extend(inc: *Incremental, a: Allocator, ctx: anytype, decode: anytype, more: []const u32) ![]const u8 {
        try inc.tokens.appendSlice(a, more);
        const before = try decode(ctx, a, inc.tokens.items[inc.prefix..inc.read]);
        const after = try decode(ctx, a, inc.tokens.items[inc.prefix..]);
        const nb = charCount(before);
        if (charCount(after) > nb and !std.mem.endsWith(u8, after, "\u{fffd}")) {
            try inc.text.appendSlice(a, afterChars(after, nb));
            inc.prefix = inc.read;
            inc.read = inc.tokens.items.len;
        }
        return inc.text.items;
    }

    /// A character is still split across tokens, so streaming waits for the rest.
    pub fn pending(inc: *const Incremental) bool {
        return inc.tokens.items.len > 0 and inc.read < inc.tokens.items.len;
    }
};
```
- **Teaching value**: you cannot stream `decode([t])` per token. The only correct incremental decode is
  "decode the window, diff against the window minus the new tokens, emit the difference" — and the *stop
  condition* is a trailing replacement character, not a byte count.
- **Gotchas**: progress is measured in **codepoints** (`charCount`), not bytes, and the trailing-U+FFFD test is
  what distinguishes "this token is genuinely an unmappable byte" from "this token is half of a CJK character".
  `(prefix, read)` is a two-cursor scheme: `prefix` is the context window start, `read` the last emitted token.

A second, byte-oriented implementation of the same idea (worth contrasting in a lesson):

## 8. The sampler

Three tiers implement the **same rule**. Order of operations is identical in all three:
**temperature → (sort / top-k select) → top-p (nucleus) → min-p → keyed Gumbel argmax**. Penalties are applied to
raw logits *before* temperature, in a separate stage.

### 8a. Reference / oracle: the full-row stable sort

- **Anchor**: `zig/src/core/lanes/sampling_reference.zig:1-23` (whole file)
- **What it does**: The test-and-benchmark oracle. It sorts the entire row `(value desc, id asc)` with no
  selection shortcuts, then calls the *unchanged* `chooseOrdered`. This is the cleanest statement of the contract:
  only candidate *selection* is optimised; the draw itself is shared.
- **Excerpt**:
```zig
//! Test and benchmark oracle: TensorFold's original full-row stable candidate sort, without selection shortcuts.
const std = @import("std");
pub const sampling = @import("sampling.zig");
const Candidate = sampling.Candidate;

fn before(_: void, a: Candidate, b: Candidate) bool {
    return a.value > b.value or (a.value == b.value and a.id < b.id);
}

pub fn ordered(gpa: std.mem.Allocator, values: []const f64, ids: []const u64) ![]Candidate {
    const order = try gpa.alloc(Candidate, ids.len);
    for (order, values, ids) |*o, v, id| o.* = .{ .value = v, .id = id };
    std.mem.sort(Candidate, order, {}, before);
    return order;
}

/// Only candidate selection changes in the optimized path; both paths use the unchanged ordered draw.
pub fn choose(gpa: std.mem.Allocator, values: []const f64, ids: []const u64, position: u64, s: sampling.Sampling) !u64 {
    const order = try ordered(gpa, values, ids);
    defer gpa.free(order);
    return sampling.chooseOrdered(gpa, order, position, s);
}
```
- **Teaching value**: start a sampler lesson here. 20 lines, no tricks, and it is the thing the fast paths are
  tested against.

### 8b. The canonical host sampler — **this is the order-of-operations anchor**

- **Anchor**: `zig/src/core/lanes/sampling.zig:135-178`
- **What it does**: `chooseOrdered` applies, in this exact order:
  1. **greedy**: `temperature <= 0` returns `order[0].id` (first maximum, ties to the lower id);
  2. **top-k**: `k = min(top_k or width, width)`, clamped to at least 1 — a pure prefix cut of the sorted order;
  3. **temperature**: `x = value / max(temperature, 1e-6)` over the k survivors;
  4. **top-p**: softmax (shifted by `scaled[0]`), `pairwiseSum` normaliser, keep `below + 1` where `below` counts
     entries whose running cumulative is strictly `< top_p`;
  5. **min-p**: an *additive* floor in log space, `scaled[0] + ln(min_p)`;
  6. **the draw**: Gumbel-max — `score = scaled[j] + (-ln(-ln(u)))` with `u = uniform(seed, position, id)`, and
     the highest score wins.
- **Excerpt**:
```zig
/// ``choose`` over candidates already in its order (by value, then the lower id at a tie).
pub fn chooseOrdered(gpa: Allocator, order: []const Candidate, position: u64, s: Sampling) !u64 {
    const width = order.len;
    if (width == 0) return error.NoAllowedToken;
    if (s.temperature <= 0) return order[0].id; // temperature 0 is greedy: the first maximum, ties to the lower id
    const k = @max(1, @min(if (s.top_k != 0) @as(usize, s.top_k) else width, width));
    const scaled = try gpa.alloc(f64, k);
    defer gpa.free(scaled);
    const t = @max(s.temperature, 1e-6);
    for (scaled, order[0..k]) |*x, o| x.* = o.value / t;
    var keep = k;
    if (s.top_p > 0.0 and s.top_p < 1.0) {
        const probs = try gpa.alloc(f64, k);
        defer gpa.free(probs);
        for (probs, scaled) |*p, x| p.* = exp(x - scaled[0]);
        const total = pairwiseSum(probs);
        var cum: f64 = 0.0;
        var below: usize = 0;
        for (probs) |*p| {
            p.* /= total;
            cum += p.*;
            if (cum < s.top_p) below += 1;
        }
        keep = @min(keep, below + 1);
    }
    if (s.min_p > 0.0) {
        const floor = scaled[0] + s.minLog();
        var n: usize = 0;
        for (scaled[0..keep]) |x| {
            if (x >= floor) n += 1;
        }
        keep = n;
    }
    var best: usize = 0;
    var best_score = -std.math.inf(f64);
    for (0..keep) |j| {
        const gumbel = -log(-log(uniform(s.seed, position, order[j].id)));
        const score = scaled[j] + gumbel;
        if (j == 0 or score > best_score) {
            best = j;
            best_score = score;
        }
    }
    return order[best].id;
}
```
- **Teaching value**: sampling is **not** "roll a die against a CDF". It is *perturb each log-probability by
  Gumbel noise and take the argmax* — mathematically equivalent, but it makes the draw a pure function of
  `(seed, position, token id)`, so there is no RNG stream to keep in sync across batches, GPUs or restarts.
- **Gotchas**:
  - The noise is keyed **per candidate token id**, not drawn sequentially:
    `uniform(seed, position, id)` → `keyBits` → splitmix64 of `(seed, position, id)` (`sampling.zig:66-85`).
    Two requests at the same position with the same seed draw identically regardless of batching.
  - `top_p` keeps `below + 1`: the *first* token whose cumulative reaches `top_p` is **included**.
  - `min_p` is implemented as an additive floor on scaled logits (`+ ln(min_p)`), never as a probability compare —
    `Sampling.minLog()` at `sampling.zig:17-19` returns `-inf` when off.
  - `pairwiseSum` (`sampling.zig:88-108`) reproduces **numpy's `np.add.reduce` blocking exactly** (8-wide
    unrolled, recursive split at 128) so the normaliser matches the Python reference bit for bit. The file header
    states the contract: "the keyed host sampler (Python exact_sampling.py) bit for bit: libm's exp and log,
    numpy's sum order" — note `extern "c" fn exp/log` at `sampling.zig:6-7`, deliberately bypassing Zig's `@exp`.
  - Default knobs live on the struct (`sampling.zig:9-14`): `temperature = 1.0, top_k = 20, top_p = 0.95,
    min_p = 0.0`.

**Fast paths inside the same file (both must agree with `chooseOrdered`):**
- `choose` (`sampling.zig:113-132`) only allocates and sorts the **full row** when nothing cheaper applies: it
  tries `selection.greedy`, then `selection.topK` when `top_k <= width/2`, then `race`.
- `race` (`sampling.zig:183-211`) finds the Gumbel winner in **one pass with no sort**, valid only when no rank
  cut applies (`top_k == 0 or >= len`, and `top_p` off). It uses a provable skip test: `skip_gaps`
  (`sampling.zig:214`) with `bounds[i] = exp(-exp(-(gap - 0.5)))` — a candidate `d` below the leader whose uniform
  is under the bound *cannot* close the gap, so its two `log` calls are skipped entirely
  (`beneath`, `sampling.zig:226-232`). Any non-finite value aborts to the full sort.
- `topK` (`sampling_selection.zig:47-72`) is a bounded min-heap that allocates exactly `k` candidates and `k`
  indices and whose comparator `Order.before` includes the **input position** as a final tiebreak, so it
  reproduces the full stable sort's order for duplicate ids and signed zero.

### 8c. Host reference of the GPU sampler

- **Anchor**: `zig/src/core/lanes/gpu_rule.zig:69-124`
- **What it does**: The same rule in `f32` with the GPU's *exact* reduction order and a 1024-candidate cap. The
  `Rule` struct (`gpu_rule.zig:14-30`) is the shared wire format: `{seed, inv_t, top_p, near, min_log, top_k}`
  packed into a 4-float `cfg` row and two `u32` seed halves for Metal. `sample()` reproduces the kernel's
  order-preserving float key (`key`, `gpu_rule.zig:38-41`), its 24-bit uniform, and its threadgroup sum.
- **Excerpt**:
```zig
/// One row's draw under the kernel's rule; `ids` maps columns to token ids (a draft head's subset vocabulary).
pub fn sample(gpa: Allocator, logits: []const f32, s: ?Sampling, position: u32, ids: ?[]const u32) !u32 {
    const st = s orelse {
        const at = argmax(logits);
        return if (ids) |m| m[at] else at;
    };
    const r = rule(st);
    const inv_t = r.inv_t;
    const cap: usize = if (kc == 0 or kc > candidates) candidates else kc;
    const all = try gpa.alloc(Cand, logits.len);
    defer gpa.free(all);
    var m = -std.math.inf(f32);
    for (all, logits, 0..) |*c, l, i| {
        c.* = .{ .v = l * inv_t, .i = @intCast(i) };
        m = @max(m, c.v);
    }
    const z = threadSum(all, m);
    std.mem.sort(Cand, all, {}, better);
    const n: usize = @min(@min(all.len, candidates), cap);
    var norm = z;
    if (kc != 0) {
        norm = 0.0;
        for (all[0..n]) |c| norm += @exp(c.v - m);
    }
    var keep: usize = n;
    if (top_p > 0.0 and top_p < 1.0) {
        var cum: f32 = 0.0;
        for (all[0..n], 0..) |c, j| {
            cum += @exp(c.v - m) / norm;
            if (cum >= top_p) {
                keep = j + 1;
                break;
            }
        }
    }
```
- **Teaching value**: an engine that must match a Python reference needs the *reduction order* written down, not
  just the formula. `lanesSum` (`gpu_rule.zig:132-145`) literally simulates a 32-lane butterfly plus 32
  simdgroups in order.
- **Gotchas**: temperature is `* inv_t` here but `/ t` in `sampling.zig` — the host sampler divides in f64, the
  GPU multiplies by a precomputed reciprocal in f32, and the file header admits the consequence: *"it can pick
  differently where scores tie within a few ulps."* With `top_k == 0` the normaliser is the **whole row's** `z`;
  with `top_k != 0` it is recomputed over the kept candidates only. `candidates = 1024` (`gpu_rule.zig:7`) and
  `near = 20.0` (`gpu_rule.zig:10`) are the two magic numbers.

### 8d. The actual Metal kernel

- **Anchor**: `zig/kernels/metal/nemotron/sample.metal:205-250`
- **What it does**: One row per 1024-thread threadgroup over `V = 131072` logits (`sample.metal:31`), `C = 1024`
  candidates (`:32`). Lines 205-225 apply the top-k/top-p/min-p cuts on thread 0 over the sorted candidates;
  227-250 run the Gumbel race in parallel (one candidate per thread) and reduce with `simd_max` / `simd_min`,
  resolving score ties to the **lower candidate index**.
- **Excerpt**:

- **Teaching value**: the keyed-Gumbel design pays off here — because the noise is a pure function of
  `(seed, position, id)`, 1024 threads can each score **their own** candidate with no shared RNG state and no
  serialisation. A CDF sampler cannot be parallelised this way.
- **Gotchas**:
  - `tf_key` (`sample.metal:7`) maps a float to an order-preserving `u32` so the sort is an **integer** bitonic
    sort (`sample.metal:186-204`).
  - Two selection strategies: a **"near window" fast path** (`sample.metal:101-121`) that keeps every logit within
    `near / 2^w` of the max for `w ∈ {0,1,2}` when that set is ≤ 1024 and already covers `top_p`, and a
    **4-pass 8-bit radix select** fallback (`sample.metal:122-184`) with a *second* 3-pass radix select over token
    **ids** to break key ties deterministically (`idcut`).
  - `tf_uniform` (`sample.metal:12-17`) is the same splitmix64 chain as `sampling.zig:66-85`, but takes the top
    **24** bits: `(float(x >> 40) + 0.5) / 2^24`, versus 53 bits in the f64 host path.
  - Sibling kernel `nemotron_sample.metal` (`tf_sample_full`) handles rows where `tf_gpu_sample`'s 1024-candidate
    cut is not valid (top-k off, or above 1024); the dispatch choice is documented at
    `zig/kernels/cuda/sample.cu:517-520`.

### 8e. Penalties (presence / frequency / repetition)

- **Anchor**: `zig/src/hip_serve/draw.zig:190-216`
- **What it does**: `process` widens the raw `bf16`/`f16` logits to `f32`, applies HF's **repetition** penalty
  (multiply if negative, divide if positive) over *prompt + reply* tokens counted once, then applies OpenAI's
  **presence + frequency** penalties as a subtraction over *reply-only* tokens counted with multiplicity. This all
  happens **before** temperature and before any cut.
- **Excerpt**:
```zig
/// HF repetition processing widens raw scores before FP32 multiply/divide; it must not round back to BF16.
pub fn process(a: std.mem.Allocator, values: []f32, r: Request) !void {
    if (!(r.repetition > 0) or !std.math.isFinite(r.repetition)) return error.BadRepetitionPenalty;
    const counts = try a.alloc(u32, values.len);
    defer a.free(counts);
    @memset(counts, 0);
    if (r.repetition != 1) {
        for (r.history) |id| {
            if (id >= values.len) return error.BadHistoryToken;
            counts[id] = 1;
        }
        for (values, counts) |*v, seen| if (seen != 0) {
            v.* = if (v.* < 0) v.* * r.repetition else v.* / r.repetition;
        };
    }
    if (r.penalties.active()) {
        @memset(counts, 0);
        for (r.reply) |id| {
            if (id >= values.len) return error.BadHistoryToken;
            counts[id] += 1;
        }
```

with the penalty formula itself at `zig/src/core/lanes/sampling.zig:27-38`:
```zig
/// OpenAI's presence and frequency penalties: a reply's token loses presence + frequency * its count, greedy too.
pub const Penalties = struct {
    presence: f32 = 0,
    frequency: f32 = 0,

    pub fn active(p: Penalties) bool {
        return p.presence != 0 or p.frequency != 0;
    }

    /// What a token held `count` times (at least once) loses from its logit.
    pub fn of(p: Penalties, count: u32) f32 {
        return p.presence + p.frequency * @as(f32, @floatFromInt(count));
    }
};
```
- **Teaching value**: two penalty families coexist and are *not* the same operation — HF's `repetition_penalty`
  is multiplicative and sign-dependent and counts the prompt; OpenAI's two are additive and count only the reply.
- **Gotchas**: the doc comment "greedy too" matters — penalties apply even at temperature 0, so they change
  greedy output. `drawHost` (`draw.zig:174-188`) has a **fast path that skips the whole widening allocation**
  when `repetition == 1 and !penalties.active()`. On CUDA the same stage is a kernel, dispatched at
  `zig/src/families/qwen3_5/cuda_engine.zig:518`:
  `if (keep == .draws or keep == .logits) try e.penalties.apply(e.d, &e.draws, e.stream, e.logits, g.vocab) else e.penalties.clear();`

```zig
        const m = g.box;
        while (true) {
            m.mutex.lockUncancelable(m.io);
            var chunk: ?[]u32 = null;
            var ended = false;
            if (g.chunk_index < m.chunks.items.len) {
                const end = m.chunks.items[g.chunk_index];
                chunk = g.a.dupe(u32, m.tokens.items[g.consumed..end]) catch |e| {
                    m.mutex.unlock(m.io);
                    return e;
                };

                g.consumed = end;

            } else {

            }

                return;

                return error.Cancelled;
```

### 9b. Stop conditions and token counting (server side)

- **Anchor**: `zig/src/server/chat_generation.zig:91-103`
- **What it does**: `commit` appends each token to `g.collected`, then checks three stop conditions in order:

  `engine.cancel`), and `collected.len >= max_tokens` (→ `"length"`). `g.collected.items.len` is the
  `completion_tokens` reported in usage.
- **Excerpt**:

## 10. Speculative decoding: proposal, acceptance, rejection

### 10a. Where a draft is accepted — the equality enforcement

- **Anchor**: `zig/src/core/lanes/accept.zig:39-62`
- **What it does**: **This is the file the task asks for.** `acceptPath` walks the verification window from row 0
  (the pending token). At each accepted row it reads `picks[at]` — the token the **target model** sampled at that
  row — and looks for the first child row whose *drafted* token equals it. A match extends the path; no match
  ends it. `targetPick` then supplies the committed token, and its doc comment states the invariant verbatim:
  *"the reply's token, never the draft's proposal."*
- **Excerpt**:
```zig
/// Rows of the accepted path from row 0: follow the first child (by row) whose token is the target's pick.
pub fn acceptPath(gpa: Allocator, tokens: []const u32, parents: []const i32, picks: []const u32) ![]u32 {
    var path: std.ArrayList(u32) = .empty;
    errdefer path.deinit(gpa);
    try path.append(gpa, 0);
    while (true) {
        const at = path.items[path.items.len - 1];
        const want = picks[at];
        var next: ?u32 = null;
        for (parents, 0..) |q, row| {
            if (q == @as(i32, @intCast(at)) and tokens[row] == want) {
                next = @intCast(row);
                break;
            }
        }
        try path.append(gpa, next orelse break);
    }
    return path.toOwnedSlice(gpa);
}

/// The target's pick at an accepted row's parent: the reply's token, never the draft's proposal.
pub fn targetPick(picks: []const u32, parents: []const i32, row: u32) u32 {
    return picks[@intCast(parents[@intCast(row)])];
}
```
- **Teaching value**: speculative decoding is **exact, not approximate**. `tokens[row] == want` is the entire
  acceptance test: a draft is kept **if and only if** it is literally the same `u32` the target model would have
  sampled at that position. Nothing probabilistic, no rejection-sampling correction — because the target's draw
  is a deterministic function of `(seed, position, id)` (§8b), "what the engine would have produced" is a value
  you can just compare against.
- **Gotchas**:
  - The committed token comes from `picks`, **never** from `tokens` — so even an accepted row contributes the
    *target's* token, which is why acceptance cannot introduce drift even if the two happened to differ.
  - This handles **trees**, not just chains: `parents` is per-row, `rowParents` (`accept.zig:6-17`) builds a chain
    when `parents` is null, and `isChain` (`accept.zig:34-37`) detects the chain case so the hot path can skip
    tree bookkeeping.
  - `depths` (`accept.zig:20-32`) returns `error.ParentAfterChild` rather than looping — the tree is validated,
    not trusted.
  - `sanitizeTree` (`accept.zig:67-86`) truncates a tree to a node budget and drops orphaned subtrees.

- **Anchor**: `zig/src/core/lanes/engine.zig:327-352`
- **What it does**: `conclude` is the per-round commit. For a non-forced round it calls `acceptPath`, builds

  `acceptance_rate` in the response's `speculative` block.
- **Excerpt**:

- **Gotchas**: `kept = path.len - 1` and `drafted = rows - 1` both exclude row 0 (the already-known pending
  token). The counters feed `observeDepth` (`depth.zig:90-99`), an exponential-moving-average estimate of
  per-depth acceptance that the depth rule uses to choose how deep to draft next round — so **rejection is a
  control signal, not just a loss**. Separate counters exist for suffix-match grafts and Recall copies

- **What it does**: `Drafted` wraps a target backend with an external drafter in front. Its `verify` is where
  held (device-resident) drafts are converted into host tokens and spliced into the verification windows before
  the target's own `verify` runs — and where a stream with no row to draft from gets its window filled with the
  **pending token** instead (so the window shape stays constant and those rows are simply wasted, never wrong).
- **Excerpt**:
```zig
    /// Held drafts reach the target as host tokens, all streams read back in one call (fillers: the pending token).
    fn verify(ptr: *anyopaque, windows: []const be.Window, out: []be.Verified) anyerror!void {
        const x = self(ptr);
        x.windows.clearRetainingCapacity();
        try x.windows.appendSlice(x.gpa, windows);
        var total: usize = 0;
        var through = x.held_on_target;
        for (windows) |w| {
            if (w.held > 0 and w.tokens.len != 0) return error.MixedDrafts;
            total += w.held;
            if (through and w.held > 0 and (x.lanes.getPtr(w.stream) orelse return error.NotDrafting).filler > 0) through = false;
        }
        if (total == 0 or through) return x.target.verify(x.windows.items, out);
        try x.tokens.resize(x.gpa, total);
        var at: usize = 0;
        for (windows, x.windows.items) |w, *v| {
            if (w.held == 0) continue;
            const lane = x.lanes.getPtr(w.stream) orelse return error.NotDrafting;
            const slot = x.tokens.items[at..][0..w.held];
            at += w.held;
            v.tokens = slot;
            v.held = 0;
            if (lane.filler > 0) {
                @memset(slot, w.pending);
                lane.filler = 0;
                continue;
            }
            try x.streams.append(x.gpa, w.stream);
            try x.outs.append(x.gpa, slot);
        }
        if (x.streams.items.len > 0) try x.drafter.held(x.streams.items, x.outs.items);
        return x.target.verify(x.windows.items, out);
    }
```
- **Teaching value**: the drafter is a *decorator* around the target backend with the same vtable — the round
  loop does not know whether drafts came from an MTP head, a separate small model, suffix lookup or Recall.
- **Gotchas**: `held_on_target` is a pass-through fast path — when the target can read the drafter's device buffer
  directly, no host round-trip happens at all. Every scratch buffer (`windows`, `tokens`, `streams`, `outs`,
  `absorbs`, `holds`, `firsts`) is kept on the struct so a steady-state round **allocates nothing**
  (`drafted.zig:22-32`). `error.MixedDrafts` enforces that a window carries either held device drafts or host
  tokens, never both.

### 10d. The engine-level identity receipt

- **Anchor**: `zig/src/server/tokens.zig:106-113` and `zig/src/server/chat_generation.zig:327-336`
- **What it does**: Every reply's `tensorfold` block carries `token_sha` / `token_sha256` over the committed id
  sequence. The doc comment states the contract tested against: *"drafted and `"draft": false` replies must match."*
- **Excerpt**:
```zig
/// The reply's token ids hashed: drafted and ``"draft": false`` replies must match.
pub fn tokenSha256(tokens: []const u32) [64]u8 {
    var h = std.crypto.hash.sha2.Sha256.init(.{});
    var buf: [16]u8 = undefined;
    for (tokens, 0..) |t, i| {
        if (i > 0) h.update(",");
        h.update(std.fmt.bufPrint(&buf, "{d}", .{t}) catch unreachable);
    }
    var d: [32]u8 = undefined;
    h.final(&d);
    return std.fmt.bytesToHex(d, .lower);
}
```
- **Teaching value**: the "accepted draft == what the engine would produce" claim is not only enforced by
  `acceptPath`; it is **observable from the HTTP response**. A lesson can have the learner send the same prompt
  twice, once with `"draft": false`, and diff two SHAs.
- **Gotchas**: the hash is over comma-joined **decimal** ids, so `{1,23}` and `{12,3}` differ (asserted in the
  test at `tokens.zig:123-135`). The acceptance rate sits next to it in the `speculative` object
  (`chat_generation.zig:349-350`).
